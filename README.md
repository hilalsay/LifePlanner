# Life Planner

A personal productivity web app for planning, habit tracking, mood logging, reading lists, and AI-powered goal coaching. Built with FastAPI, React, and PostgreSQL.

## Features

- **Planning ladder** — Vision → Month → Week → Today. Six pages: Today, Week, Month, Vision, Habits, Reading
- **Today** — tasks, one-tap habit chips, an autosaving daily check-in (mood, energy, sleep, water), and "Move to today" for unfinished tasks from the past week. Open any day with `/today?date=YYYY-MM-DD`
- **Natural-language quick add** — type `Dentist tomorrow 10am !high` (English or Turkish); parsed on the device with a live preview
- **Week & Month** — week tiles show done/total per day and can add a weekly priority to today; month has an interactive mood calendar with a day summary
- **Vision** — yearly goals with a year switcher and one-tap completion
- **Habit tracker** — define daily/weekly habits and log completions
- **Reading list** — track books with Google Books search (covers auto-filled), star ratings, written reviews, and progress pages
- **AI assistant (AIzen)** — conversational goal coach that suggests tasks, habits, and priorities; runs on a local Ollama model or Google Gemini
- **Weekly AI review** — automatic narrative summary of your week, generated by the same AI provider
- **Daily motivation** — a witty motivational line on the dashboard, AI-generated or from a built-in fallback set
- **Settings** — avatar upload, language toggle (English / Turkish), hide-completed preference
- **Installable PWA** — add to home screen / desktop; service worker precaches the app shell for fast loads and offline launch
- **Auth** — email/password registration and Google sign-in; JWT via httponly cookies
- **Admin panel** (`/admin`) — for admin users: KPIs, daily active users, sign-ups, feature adoption, and a searchable user table with per-user drill-down. Only request counts are tracked, never content
- **Security hardening** — per-IP rate limits on auth, AI and search endpoints, cross-site request (Origin) checks, a 256 KB JSON body cap, content-sniffed avatar uploads, and a refusal to start in production with weak secrets

## Tech stack

| Layer | Tech |
|---|---|
| Backend | FastAPI, SQLAlchemy 2, Alembic, Pydantic v2, PyJWT, passlib |
| Database | PostgreSQL 16 |
| Frontend | React 18, TypeScript, Vite, Tailwind CSS, shadcn/ui, react-router-dom |
| AI | Ollama (local, e.g. `qwen2.5:3b`) or Google Gemini (`gemini-2.5-flash-lite`); optional OpenAI-compatible API for admins |

- Python 3.12

## Quick start

```bash
# 1. Clone
git clone https://github.com/hilalsay/LifePlanner.git
cd LifePlanner

# 2. Create your environment file
cp .env.example backend/.env
# Edit backend/.env — at minimum add GEMINI_API_KEY (see Environment variables below)

# 3. Install everything and set up the database
./setup.sh

# 4. Start
./start.sh
```

`setup.sh` installs system packages (apt), creates a Python venv, installs Python and npm dependencies, creates the `lifeplanner` PostgreSQL user and `life_planner` database, and runs Alembic migrations.

`start.sh` starts PostgreSQL, runs any new migrations, starts the backend on port 8000, starts the frontend on port 5173, and monitors both processes. Press **Ctrl+C** to stop everything.

Open **http://localhost:5173** in your browser.

## Using Docker for the database

If you prefer Docker instead of a local PostgreSQL install:

```bash
docker compose up -d   # starts postgres:16-alpine on port 5432
```

Then run `./setup.sh` (it will skip the PostgreSQL install step if the port is already open) and `./start.sh` as normal.

## Environment variables

Create `backend/.env` (copy from `.env.example` in the repo root).

### Required

| Variable | Description |
|---|---|
| `DATABASE_URL` | PostgreSQL DSN. Default: `postgresql://lifeplanner:lifeplanner123@localhost:5432/life_planner` |

### AI provider

| Variable | Default | Description |
|---|---|---|
| `AI_PROVIDER` | `gemini` | `ollama` or `gemini`. Powers the AIzen assistant, the weekly review, and the motivational message |
| `GEMINI_API_KEY` | — | Required when `AI_PROVIDER=gemini`. Get one at [aistudio.google.com](https://aistudio.google.com) |
| `OLLAMA_BASE_URL` | — | Required when `AI_PROVIDER=ollama`. E.g. `http://localhost:11434` |
| `OLLAMA_MODEL` | `qwen2.5:3b` | Model to use with Ollama |
| `OLLAMA_HOST_HEADER` | `127.0.0.1` | Ollama's DNS-rebind guard; leave as-is for local installs |
| `EXTERNAL_AI_BASE_URL` | — | Optional OpenAI-compatible API used **only for admin users** |
| `EXTERNAL_AI_API_KEY` | — | API key for the external provider |
| `EXTERNAL_AI_MODEL` | — | Model name for the external provider |
| `GOOGLE_BOOKS_API_KEY` | — | Optional; raises Google Books search rate limits |

### Security (change in production)

| Variable | Default | Description |
|---|---|---|
| `JWT_SECRET_KEY` | *(placeholder)* | Sign JWTs. Generate with `openssl rand -hex 32` |
| `SESSION_SECRET_KEY` | *(placeholder)* | Sign OAuth session cookies. Use a separate random value |
| `ENVIRONMENT` | `development` | Set `production` on the server. The backend then refuses to start if the JWT/session secrets are placeholders or shorter than 32 characters, or if `COOKIE_SECURE` is off |
| `COOKIE_SECURE` | `false` | Set `true` in production (requires HTTPS) |
| `ACCESS_TOKEN_EXPIRE_MINUTES` | `15` | Access token lifetime |
| `REFRESH_TOKEN_EXPIRE_DAYS` | `7` | Refresh token lifetime |

### OAuth (optional)

| Variable | Description |
|---|---|
| `GOOGLE_CLIENT_ID` | Google OAuth app client ID |
| `GOOGLE_CLIENT_SECRET` | Google OAuth app client secret |
| `GITHUB_CLIENT_ID` | GitHub OAuth app client ID (backend only; no login button in the UI) |
| `GITHUB_CLIENT_SECRET` | GitHub OAuth app client secret |

For Google OAuth, set the authorized redirect URI to `http://localhost:8000/api/v1/auth/google/callback`.
Google sign-in links to an existing account only when Google reports the email as verified.

### URLs

| Variable | Default | Description |
|---|---|---|
| `FRONTEND_URL` | `http://localhost:5173` | Added to CORS allowed origins; set to your production domain |
| `BACKEND_URL` | `http://localhost:8000` | Used in OAuth redirect URIs |

## AI provider configuration

### Gemini (default)

```env
AI_PROVIDER=gemini
GEMINI_API_KEY=AIza...
```

The assistant uses `gemini-2.5-flash-lite`. The free tier is sufficient for personal use.

### Ollama (local / offline)

```bash
# Install Ollama, then pull a model
ollama pull qwen2.5:3b
```

```env
AI_PROVIDER=ollama
OLLAMA_BASE_URL=http://localhost:11434
OLLAMA_MODEL=qwen2.5:3b
```

Any instruction-following model works. Larger models give better goal suggestions; `qwen2.5:3b` runs well on CPU.

> The selected provider drives every AI feature — the AIzen chat assistant, the weekly review, and the daily motivational line. There is no dependency on a paid Claude/Anthropic key; if a feature can't reach its provider, the motivational line falls back to a built-in set and the weekly review reports that the provider is unavailable.

## Admin users

There is no UI for granting admin rights. Set the flag in the database:

```sql
UPDATE users SET is_admin = true WHERE email = 'you@example.com';
```

Admins see the **Admin** page at `/admin`, and their AI requests use the external provider when `EXTERNAL_AI_*` is configured.

## Production deployment

Before exposing the app publicly:

1. **Generate strong secrets**

   ```bash
   openssl rand -hex 32   # use for JWT_SECRET_KEY
   openssl rand -hex 32   # use for SESSION_SECRET_KEY
   ```

2. **Enable secure cookies** — set `COOKIE_SECURE=true` and serve the app over HTTPS.

3. **Set the database password** — change the default `lifeplanner123` in `docker-compose.yml` and `DATABASE_URL`.

4. **Set `FRONTEND_URL`** to your production domain so CORS is correct.

5. **Set `ENVIRONMENT=production`** so the backend refuses to start with weak secrets.

6. **Run the backend with a process manager** instead of the dev `--reload` server. The repo ships systemd units in `deploy/systemd/`:
   - `lifeplanner-backend.service` — uvicorn on port 8000; runs migrations on start
   - `lifeplanner-frontend.service` — oneshot `npm run build` into `frontend/dist/`
   - nginx serves `frontend/dist/` and proxies `/api` to port 8000

7. **Add security headers** — `deploy/nginx-security-headers.conf` holds the header snippet; `sudo deploy/apply-nginx-security.sh` adds it to the nginx server block, validates the config, and rolls back on failure.

### Redeploying

Run `deploy.sh` on the server. It pulls `main` (fast-forward only), updates backend dependencies (falling back to `uv` if the venv has no pip), rebuilds the frontend, and restarts the services:

```bash
ssh <user>@<server> 'cd ~/LifePlanner && ./deploy.sh'
```

The public OpenAPI docs (`/docs`, `/redoc`, `/openapi.json`) are disabled in every environment.

## API

All endpoints are prefixed `/api/v1`. Key groups:

| Prefix | Description |
|---|---|
| `/auth` | Register, login, logout, OAuth (Google, GitHub), avatar upload |
| `/planning` | Monthly focuses, weekly priorities, daily tasks |
| `/habits` | Habit definitions and completion logs |
| `/tracking` | Mood, health, books, weekly reviews |
| `/ai` | Chat assistant, natural-language task parsing |
| `/admin` | Overview, users, per-user usage (admin users only) |

Sensitive endpoints are rate-limited per client IP.
